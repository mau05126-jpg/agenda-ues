02
Antecedentes · Planteamiento del problema

¿Qué problema resuelve?

📍 Contexto situacional

La 12va Jornada Académica y Cultural 2025 de la UES San José del Rincón concentra múltiples sesiones, escenarios simultáneos y cientos de estudiantes. Sin un sistema digital, la coordinación dependía de procesos manuales: listas en papel, hojas de cálculo y comunicación informal — generando errores, pérdida de información y cero trazabilidad.

Antes de Agenda UES, estos eran los problemas concretos:

📋
Sin agenda personalizada
Los estudiantes no podían consultar qué sesiones asistir ni gestionar su horario propio.
📊
Gestión manual del admin
Registrar sesiones, ponentes y escenarios requería hojas de cálculo y trabajo manual repetitivo.
📄
Sin comprobantes digitales
No existía forma de exportar un PDF oficial con las sesiones inscritas del estudiante.
🔐
Sin acceso seguro
No había sistema de autenticación con roles diferenciados para administrador y estudiante.
✅ Agenda UES resuelve todo esto — sistema centralizado, seguro y accesible desde cualquier dispositivo. Costo total: $0/mes.

🗂️ Glosario técnico

Conceptos clave del proyecto

Cada término aparece en el código real de Agenda UES — entenderlos es entender cómo funciona el sistema.

Arquitectura · Despliegue · Rendimiento
🧱
JAMstack
JavaScript · APIs · Markup
Frontend estático + APIs independientes. Agenda UES: React en Vercel CDN llamando a Vercel Functions.
⚡
Serverless
Funciones bajo demanda
Código que corre solo cuando se invoca. Cada endpoint de Agenda UES es una función independiente en Vercel.
🌐
CDN
Content Delivery Network
Red global de servidores. Vercel sirve Agenda UES desde el nodo más cercano al visitante, sin latencia.
🔄
CI/CD
Integración · Entrega continua
Cada push a GitHub despliega automáticamente en Vercel. El código llega a producción en segundos.
🔃
SWR
Stale-While-Revalidate
Muestra caché al instante y actualiza en segundo plano. La agenda del estudiante aparece sin esperar al servidor.
🔌
REST API
Representational State Transfer
18 endpoints HTTP en Agenda UES: /api/sesiones, /api/login. Responden JSON.
Seguridad · Autenticación · Datos
🪙
JWT
JSON Web Token
Token firmado entregado al hacer login. El frontend lo adjunta en cada petición para probar identidad sin consultar la BD.
🚧
CORS
Cross-Origin Resource Sharing
Política que controla qué dominios consumen la API. Configurado para admitir solo el frontend de Agenda UES.
🆔
UUID
Universally Unique Identifier
ID de 36 caracteres aleatorio. Evita IDs predecibles que un atacante podría enumerar en la base de datos.
🔒
Hash / bcrypt
One-way encryption
Convierte contraseñas en hash irreversible. Ni el admin puede ver la clave real — solo se compara hash con hash.
💉
SQL Injection
Ataque de inyección
Inyecta SQL malicioso en inputs. Prevenido con consultas parametrizadas en Neon PostgreSQL.
📨
SMTP
Simple Mail Transfer Protocol
Protocolo de envío de email. Implementado vía Google Apps Script como servidor SMTP gratuito.
Cada uno de estos conceptos está en el código fuente de Agenda UES — no son teoría, son decisiones de diseño reales.

/api/inscribir.js 
import { pool } from '../lib/db.js';
import { verifyJWT } from '../lib/auth.js';

// Verifica JWT → inscribe con params seguros
export default async function handler(req, res) {
  const { userId } = verifyJWT(req.headers.authorization);
  const { sesionId } = req.body;

  await pool.query(
    'INSERT INTO inscripciones VALUES ($1, $2)',
    [userId, sesionId]  // SQL Injection imposible
  );
  res.json({ ok: true });
}
/api/login.js — JWT 
import bcrypt from 'bcryptjs';
import jwt from 'jsonwebtoken';

// Verifica contraseña y emite token
const valid = await bcrypt.compare(
  password, user.password_hash
);
if (!valid) return res.status(401).json({...});

const token = jwt.sign(
  { userId, rol, matricula },
  process.env.JWT_SECRET,
  { expiresIn: '7d' }  // expira en 7 días
);
res.json({ token });

08
Seguridad

JWT + bcryptjs — Autenticación robusta

🔐jsonwebtoken v9
Tokens sin sesiones en servidor
Al hacer login, el servidor genera un token firmado con id, email, matrícula y rol.

El token va en localStorage. El servidor lo verifica con la clave secreta — sin consultar la BD en cada petición.

Expira en 7 días automáticamente.
🧂bcryptjs v3
Hash con 10 rondas de sal
Las contraseñas nunca se guardan en texto plano en la base de datos.

Se convierten con 10 rondas de salt en un hash irreversible único.

bcrypt.compare() verifica sin descifrar — si alguien roba la BD, las contraseñas son inútiles.
⏰ Expiración del token: El JWT dura 7 días. Sin logout en servidor — si el token es robado, simplemente expira solo.
🛡️ Control de roles: El token incluye el campo rol. Cada endpoint verifica el rol antes de ejecutar cualquier operación sensible.
🔑 Recuperación — UUID + Google Apps Script
1
Usuario ingresa su email en el formulario
↓
2
UUID v4 generado — token de 128 bits imposible de adivinar
↓
3
Token guardado en tabla password_resets con expires_at
↓
4
Google Apps Script envía el email con el enlace
↓
5
Token validado, eliminado de BD, contraseña actualizada
¿Por qué estas tecnologías?
  • 🎲
    UUID v4 — 128 bits aleatorios. La probabilidad de adivinar el token es matemáticamente casi cero.
  • 📧
    Google Apps Script — Email gratuito con Gmail. Sin SMTP propio ni servicios de pago.
  • ♻️
    Un solo uso — Una vez usado el token se elimina. No puede reutilizarse aunque sea interceptado.
  • ⏳
    Expiración — El token tiene fecha límite. Si no se usa a tiempo, deja de funcionar automáticamente.

Performance & Despliegue

Cero downtime, cero costo

⚡ Caché localStorage — Patrón SWR
  • ⚡
    Carga instantánea — El estado se inicializa desde localStorage. El usuario ve datos de inmediato mientras la API responde.
  • 🔄
    Actualización silenciosa — La petición a la API corre en background. Si hay cambios, actualiza sin mostrar "loading".
  • 📦
    Patrón SWR — Stale While Revalidate. Mismo principio que usa Next.js: muestra datos viejos mientras revalida.
  • 🔀
    Sincronización en dos pasos — Muestra caché primero, luego compara y actualiza solo lo que cambió.
📊 Resultado: La agenda aparece instantáneamente aunque el servidor tarde 300ms. Experiencia nativa, no web.

    theme — Preferencia dark / light

    resetToken — UUID temporal (recuperación)

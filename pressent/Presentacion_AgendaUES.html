Buenos días, buenas tardes. Mi nombre es [tu nombre], soy estudiante de [tu carrera] aquí en la Universidad Mexiquense del Bicentenario, campus San José del Rincón.

El día de hoy les voy a presentar AgendaUES, un sistema web que desarrollé para gestionar la 12va Jornada Académica y Cultural 2025 de nuestra universidad.

2
¿Qué es AgendaUES? — El Problema que Resuelve
~2 minutos

Cuando se organiza un evento como la Jornada Académica, siempre hay el mismo problema: la información está dispersa. Los alumnos no saben a qué hora es cada conferencia, en qué salón, si hay cupo disponible, o cómo llevar el registro de a qué sesiones se inscribieron.

AgendaUES nace para resolver exactamente eso. Es una plataforma web completa que tiene dos grandes partes.

La primera parte es el portal público: cualquier persona puede entrar sin registrarse, ver el cronograma completo de la semana, explorar los escenarios y las sesiones disponibles, y ver cuántos lugares quedan en cada uno.

La segunda parte es para los estudiantes registrados: se pueden inscribir a las sesiones que les interesen, ver su agenda personalizada y generar un PDF oficial con un código QR que funciona como su credencial de acceso al evento.

Y la tercera parte es el panel de administración: el administrador puede desde su dashboard crear sesiones, gestionar ponentes, ver quién está inscrito, controlar los cupos de cada escenario y exportar reportes oficiales en PDF.

Nota: Si tienes el sistema abierto en pantalla, este es buen momento para mostrar brevemente la pantalla principal.
3
Arquitectura General — JAMstack
~2 minutos

Antes de hablar de cada tecnología en particular, quiero explicar la arquitectura general, porque es la base de todo.

El sistema sigue lo que se conoce como arquitectura JAMstack: JavaScript, APIs y Markup. La idea central es separar completamente el frontend del backend.

El frontend es todo lo que el usuario ve: los componentes visuales, las pantallas, los formularios. Está construido con React y se sirve como archivos estáticos desde una red de distribución global llamada CDN, lo que hace que el sitio cargue muy rápido desde cualquier parte del mundo.

El backend son funciones serverless desplegadas en Vercel. No hay un servidor tradicional corriendo las 24 horas. En cambio, cada vez que el frontend necesita datos, activa una función específica que hace la consulta a la base de datos y responde. Esto reduce costos enormemente y escala automáticamente.

La base de datos es PostgreSQL alojada en un servicio en la nube llamado Neon, que también es serverless. Y para el envío de correos en la recuperación de contraseña, uso Google Apps Script, que es completamente gratuito.

Esta arquitectura me permitió desarrollar y desplegar el sistema completo sin ningún costo, usando los planes gratuitos de Vercel, Neon y Cloudinary.

4
Frontend — React 19, Vite 8 y Tailwind CSS
~2 minutos

Para el frontend elegí React en su versión 19. React es la librería de JavaScript más usada en la industria para construir interfaces web. La razón principal por la que lo elegí es el concepto de componentes: en lugar de tener una página HTML gigante, el sistema está dividido en piezas reutilizables. Por ejemplo, la Navbar es un componente, el HeroSection es otro, el AdminDashboard es otro. Cada uno tiene su propio estado y lógica, y eso hace el código muy organizado y fácil de mantener.

Como herramienta de construcción usé Vite en su versión 8. Vite reemplaza a herramientas antiguas como Webpack y hace que el servidor de desarrollo arranque en menos de un segundo. Cuando hago un cambio en el código, se refleja en el navegador instantáneamente, lo que acelera mucho el desarrollo.

Para los estilos use Tailwind CSS. Tailwind es un framework de CSS utilitario: en lugar de escribir hojas de estilo separadas, las clases de estilo se aplican directamente en el componente. Por ejemplo, en vez de crear una clase llamada "botón-verde", simplemente escribo bg-green-800 rounded-xl px-4 py-2 y Tailwind genera el CSS correspondiente. Al final, el archivo de estilos resultante es muy pequeño porque Tailwind elimina automáticamente todas las clases que no se usaron.

Una característica muy útil de Tailwind que use bastante es el soporte para dark mode y para estilos de impresión, que les voy a explicar en un momento.

5
Funcionalidades Visuales — Carrusel, Dark Mode, Animaciones, QR
~2 minutos

Quiero destacar cuatro funcionalidades visuales específicas porque cada una usa una técnica diferente.

La primera es el carrusel infinito de instituciones participantes en la página principal. Muchos proyectos instalan librerías externas pesadas para hacer carruseles. Yo lo implementé únicamente con CSS y la propiedad @keyframes, sin ninguna librería adicional. La técnica consiste en duplicar el arreglo de imágenes y animar el contenedor para que se desplace horizontalmente al -50% de su ancho. Cuando la animación llega al final, reinicia exactamente donde empezó y el ojo no percibe ningún salto. Además, al pasar el mouse, la animación se pausa automáticamente.

La segunda es el modo oscuro. El sistema detecta la preferencia del usuario y la guarda en localStorage para que persista entre visitas. Técnicamente funciona agregando o quitando la clase dark al elemento HTML raíz, y Tailwind tiene variantes de clase como dark:bg-gray-900 que se activan solo cuando esa clase está presente.

La tercera son las animaciones de los modales y componentes. Para esto usé Framer Motion, una librería de animaciones para React. Me permite definir el estado inicial, el estado final y la transición de cualquier elemento, y también controla las animaciones de salida antes de que el componente se quite del DOM.

Y la cuarta es el código QR en la agenda del estudiante. Use la librería qrcode.react que genera el código como un SVG vectorial, lo que significa que se ve perfectamente en cualquier tamaño, incluyendo cuando se imprime el PDF. El QR contiene la matrícula del estudiante y los identificadores de sus sesiones inscritas.

6
El PDF Imprimible — Sin Librerías, Solo CSS
~2 minutos

Esta es una de las partes que más me gustó desarrollar porque la solución es completamente diferente a lo que uno esperaría.

Cuando pensamos en generar un PDF desde una aplicación web, lo primero que se nos ocurre es instalar una librería como jsPDF o html2pdf. El problema es que esas librerías tienen muchas limitaciones: no respetan todos los estilos CSS, no renderizan bien las fuentes personalizadas, y añaden mucho peso al proyecto.

La solución que encontré fue usar directamente la función nativa del navegador: window.print(). Todos los navegadores modernos tienen un motor de impresión que puede convertir cualquier página web a PDF, y ese motor respeta absolutamente todos los estilos CSS, incluyendo tablas, degradados y fuentes de íconos.

La clave está en cómo se controla qué se imprime y qué no. Tailwind CSS tiene variantes de clase especiales que solo se aplican durante la impresión, como print:hidden para ocultar elementos, o print:p-[2cm] para aplicar márgenes de 2 centímetros. Con esto, la barra de herramientas con el botón de imprimir y los controles de zoom desaparecen en el PDF.

Para eliminar la fecha, la URL y el número de página que el navegador agrega automáticamente en cada impresión, use la regla CSS @page con margin: 0. Eso elimina el área de encabezado y pie de página del navegador, y los márgenes de 2 centímetros los pongo yo directamente en el contenido del documento.

El resultado es un reporte oficial con el logo de la universidad, tabla de sesiones con horarios, ponentes y escenarios, todo en tamaño carta, con colores institucionales preservados en la impresión.

Nota: Si tienes el sistema disponible, este es buen momento para demostrar el PDF: hacer clic en "Imprimir" y mostrar la vista previa de impresión.
7
Backend — Vercel Serverless Functions
~2 minutos

Ahora hablo del backend. En lugar de tener un servidor Express corriendo las 24 horas, use lo que se llama funciones serverless.

La idea es simple: cada archivo JavaScript dentro de la carpeta /api del proyecto se convierte automáticamente en un endpoint de API. Por ejemplo, el archivo api/auth/login.js responde a peticiones en la ruta /api/auth/login. El archivo api/sesiones/listar.js responde en /api/sesiones/listar. Y así con cada funcionalidad.

Cada función exporta un handler, que es la función que Vercel llama cada vez que llega una petición HTTP. Dentro del handler se valida el método, se manejan los CORS, se hace la consulta a la base de datos y se regresa la respuesta en formato JSON.

En total el sistema tiene 18 endpoints: autenticación, registro, sesiones, inscripciones, escenarios, administración y recuperación de contraseña.

Una ventaja muy importante de este enfoque es que no hay un servidor que mantener ni que pagar. Vercel ejecuta las funciones solo cuando hay una petición, y el costo es proporcional al uso. Para un evento académico universitario, el plan gratuito es más que suficiente.

8
Base de Datos — PostgreSQL en Neon
~1 minuto

Para la base de datos usé PostgreSQL, que es uno de los sistemas de base de datos relacionales más robustos y confiables que existen. Es open source y tiene soporte completo para consultas SQL complejas, relaciones entre tablas y transacciones.

La base de datos está alojada en Neon, que es un servicio de PostgreSQL en la nube que también sigue el modelo serverless: la instancia se duerme cuando no hay actividad y despierta automáticamente cuando llega una petición. Esto reduce el consumo de recursos y entra en el plan gratuito.

El esquema tiene cinco tablas principales: usuarios, sesiones, inscripciones, password_resets y actividad_log. Para conectar Node.js con PostgreSQL use la librería pg, que es el driver oficial, y todas las consultas son parametrizadas para prevenir inyecciones SQL.

9
Autenticación — JWT y bcryptjs
~2 minutos

El sistema de autenticación usa dos tecnologías en combinación: JWT para los tokens de sesión y bcryptjs para las contraseñas.

Empiezo con bcryptjs. Una regla fundamental en seguridad web es que jamás se guarda una contraseña en texto plano en la base de datos. Si alguien accediera a la base de datos, no tendría que ver ninguna contraseña real. Lo que se guarda es un hash: una cadena cifrada de 60 caracteres que no puede revertirse a la contraseña original. Cuando el usuario inicia sesión, bcryptjs compara la contraseña que ingresó con el hash guardado, y si coinciden, le permite el acceso.

Ahora para los tokens de sesión use JSON Web Tokens, o JWT. Cuando el usuario inicia sesión correctamente, el servidor genera un token firmado digitalmente que contiene información del usuario: su id, su correo, su matrícula y su rol, que puede ser estudiante o admin. Este token se guarda en el navegador del usuario y se envía con cada petición a rutas protegidas.

Lo importante de los JWT es que son stateless, sin estado. El servidor no necesita guardar sesiones en la base de datos. Cada token se verifica automáticamente con una clave secreta, y si alguien intenta modificarlo, la firma digital queda inválida. El token expira en 7 días, después de lo cual el usuario debe iniciar sesión de nuevo.

En las rutas de administración, el backend no solo verifica que el token sea válido, sino que también verifica que el campo rol dentro del token diga "admin". Si alguien intenta acceder a rutas de administración con una cuenta de estudiante, recibe un error 403 de acceso denegado.

10
Recuperación de Contraseña — UUID + Google Apps Script
~2 minutos

La recuperación de contraseña es la funcionalidad más compleja del proyecto porque involucra tres tecnologías trabajando juntas.

El flujo es el siguiente: el usuario pone su correo en el formulario de "Olvidé mi contraseña". El backend genera un UUID, que es un identificador único universal, una cadena de 36 caracteres completamente aleatoria que es estadísticamente imposible de adivinar. Ese UUID se guarda en una tabla llamada password_resets en la base de datos, junto con una fecha de expiración de una hora. Se construye un enlace único con ese token y se le envía por correo al usuario.

Para el envío del correo use Google Apps Script. Esto es algo que mucha gente no conoce pero es muy poderoso: Google permite crear scripts en la nube que pueden enviar correos electrónicos usando Gmail, de forma completamente gratuita. Creé un script en Google Apps Script que expone una URL pública. Mi backend llama a esa URL enviando el destinatario, el asunto y el cuerpo del mensaje, y el script de Google se encarga de enviar el correo. Esto evita tener que pagar por servicios como SendGrid o configurar servidores SMTP complejos.

Cuando el usuario hace clic en el enlace del correo, llega a la página de restablecimiento con el token en la URL. El frontend extrae ese token, lo guarda en localStorage y le muestra el formulario de nueva contraseña. Cuando el usuario envía la nueva contraseña, el backend verifica que el token exista en la base de datos y que no haya expirado, compara la hora actual con la hora de expiración usando el reloj de PostgreSQL para evitar diferencias de zona horaria. Si todo está bien, hashea la nueva contraseña con bcrypt, la actualiza en la base de datos y elimina el token de un solo uso.

Una medida de seguridad importante: si el correo no existe en la base de datos, el sistema responde con el mismo mensaje que si sí existiera. Esto evita que alguien use el formulario para descubrir qué correos están registrados.

11
Despliegue en Vercel y Cierre
~2 minutos

El sistema está desplegado en Vercel. El proceso de despliegue es completamente automático: el repositorio del código está en GitHub, y cada vez que subo un cambio con git push, Vercel detecta el cambio automáticamente, ejecuta el proceso de construcción, y en menos de treinta segundos el sistema está actualizado en producción. Eso se llama integración y despliegue continuo, o CI/CD.

Las claves secretas como la contraseña de la base de datos o la clave de los tokens JWT nunca se suben al código. Se configuran directamente en el panel de Vercel como variables de entorno, y Vercel las inyecta en las funciones serverless en tiempo de ejecución.

Para resumir: AgendaUES es un sistema web completo que resuelve la gestión de un evento académico universitario real. Usa React con Vite para el frontend, Tailwind CSS para los estilos, Framer Motion para las animaciones, qrcode.react para los códigos QR, CSS puro para el carrusel y para la generación de PDF sin librerías externas. En el backend usa funciones serverless de Vercel con Node.js, PostgreSQL en Neon para la base de datos, JWT y bcryptjs para la autenticación segura, UUID y Google Apps Script para la recuperación de contraseña, y Cloudinary para el almacenamiento de imágenes. Todo desplegado gratuitamente en Vercel.

El proyecto demuestra que con las herramientas correctas es posible construir un sistema profesional, seguro y funcional sin necesidad de infraestructura costosa, y que puede escalar según las necesidades del evento.

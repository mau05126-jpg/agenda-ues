El problema

Antes de AgendaUES

Organizar la Jornada Académica siempre tuvo los mismos problemas.

😕
Información dispersa
Los estudiantes no sabían horarios, escenarios ni cupos disponibles. Todo era por rumores o volantes físicos.
📋
Sin control de inscripciones
No había forma de registrar quién asistió a cada sesión ni cuántos lugares quedaban disponibles en tiempo real.
🗂️
Gestión manual
Los organizadores manejaban todo en hojas de cálculo. Sin reportes automáticos ni estadísticas del evento.
AgendaUES centraliza toda la información del evento en una plataforma web accesible desde cualquier dispositivo, para estudiantes y administradores.
La solución

¿Qué hace AgendaUES?

Una plataforma con tres módulos pensados para tres tipos de usuarios diferentes.

🌐
Portal público
Cualquier persona, sin registro, puede ver el cronograma completo de la semana, los escenarios disponibles y los cupos en tiempo real.
🎓
Módulo del estudiante
El estudiante se registra, se inscribe a las sesiones que le interesan y descarga un PDF oficial con sello institucional y folio único.
⚙️
Panel de administración
El administrador gestiona sesiones, ponentes y cupos. Visualiza estadísticas del evento y genera reportes en PDF imprimibles.
Arquitectura

Arquitectura JAMstack

Separación total entre lo que ve el usuario y la lógica del servidor. Más rápido, más barato y más escalable.

⚛️
Frontend
Archivos estáticos servidos desde una red CDN global. El sitio carga desde el servidor más cercano al usuario. Velocidad máxima.
⚡
Backend Serverless
No hay un servidor corriendo las 24 horas. Las funciones se activan solo cuando hay una petición. Costo proporcional al uso real.
🗄️
Base de datos en la nube
PostgreSQL serverless en Neon. Se duerme cuando no hay actividad y despierta automáticamente. Plan gratuito con 512 MB.

Frontend

React 19 + Vite 8

Las herramientas más usadas en la industria para construir aplicaciones web modernas.

  • ⚛️
    React 19 — La interfaz está dividida en componentes reutilizables. Navbar, HeroSection, AdminDashboard: cada uno funciona de forma independiente con su propia lógica.
  • ⚡
    Vite 8 — Herramienta de desarrollo ultra-rápida. El servidor arranca en menos de 1 segundo. Los cambios en el código se reflejan en el navegador al instante.
  • 🔀
    Navegación propia — La app no recarga la página al cambiar de sección. Todo ocurre dentro de un solo archivo HTML cargado una sola vez.
  • 🧠
    Estado compartido (Context API) — Las páginas del panel admin comparten datos sin duplicarlos. Si se edita una sesión, todos los módulos se actualizan.

Estilos

Tailwind CSS 3

Framework de estilos que elimina la necesidad de escribir hojas de estilo separadas.

🎨
Estilos en el componente
En lugar de crear archivos CSS separados y nombrar clases, los estilos se aplican directamente donde se necesitan. Desarrollo más rápido.
🌙
Dark Mode integrado
El sistema detecta la preferencia del usuario o permite cambiarla manualmente. La preferencia se guarda para futuras visitas.
📱
Diseño responsivo
El sistema se adapta automáticamente a celular, tablet y escritorio. Sin media queries manuales. Funciona en cualquier pantalla.
Ventaja clave: Tailwind elimina automáticamente todos los estilos no utilizados antes de publicar el sitio. El resultado es un archivo CSS muy pequeño que carga en milisegundos.

Documentos oficiales

PDF oficial — sin librerías externas

El navegador tiene su propio motor de impresión. AgendaUES lo aprovecha para generar documentos perfectos.

  • 🖨️
    Sin jsPDF ni html2pdf — Se usa directamente la función del navegador que también usa el botón "Imprimir" de cualquier página web. El resultado es idéntico visualmente.
  • 🗓️
    Sin fecha ni URL del navegador — Por defecto el navegador agrega la fecha, la URL y el número de página. Con una regla CSS se elimina completamente ese área.
  • 📐
    Márgenes de 2 cm en los 4 lados — El documento se imprime en tamaño carta con márgenes precisos, igual que un documento institucional.
  • 🎨
    Colores preservados — Los fondos verdes, degradados y colores institucionales se mantienen exactamente igual en el PDF impreso.
📄
Reporte del Administrador
Tabla completa con todas las sesiones del evento, horarios, ponentes y escenarios. Con logo institucional y sello oficial.
🎓
Agenda del Estudiante

Backend

Backend — Funciones Serverless

Sin servidor dedicado. Cada función del sistema es un archivo independiente que se activa solo cuando se necesita.

  • 📁
    Cada archivo en la carpeta /api se convierte automáticamente en un endpoint de la plataforma Vercel.
  • 💤
    Las funciones no consumen recursos cuando nadie las usa. Solo se activan al recibir una petición del frontend.
  • 📈
    Escalado automático — Si 500 estudiantes usan el sistema al mismo tiempo, Vercel crea instancias adicionales de forma automática.
  • 🔒
    Cada función valida las credenciales del usuario antes de ejecutarse. Las rutas de administración requieren un token con rol de admin.

Base de datos

PostgreSQL en Neon

Base de datos relacional profesional alojada en la nube, sin costo para proyectos académicos.

  • ☁️
    Neon es PostgreSQL serverless en la nube. La base de datos se duerme cuando no hay actividad y despierta sola al recibir una consulta.
  • 🛡️
    Las contraseñas nunca se guardan en texto plano. Solo se almacena el hash cifrado, irreversible, generado con bcrypt.
  • 🔗
    Las 5 tablas están relacionadas entre sí. Un estudiante puede tener muchas inscripciones, y cada inscripción apunta a una sesión específica.
Plan gratuito de Neon: 512 MB de almacenamiento, más que suficiente para gestionar un evento universitario completo.

Seguridad

Autenticación — JWT + bcryptjs

Dos tecnologías que trabajan juntas para garantizar que cada usuario sea quien dice ser.

🔐
bcryptjs — Hash de contraseñas
La contraseña nunca se guarda tal cual en la base de datos. Se convierte en un código cifrado de 60 caracteres que es imposible de revertir. Aunque alguien acceda a la BD, no ve las contraseñas reales.
🎫
JWT — Token de sesión
Al iniciar sesión, el servidor entrega un token firmado digitalmente que contiene el nombre, correo y rol del usuario. Ese token expira en 7 días y no puede falsificarse.
🛡️
Control por roles
El token identifica si el usuario es estudiante o administrador. Las páginas del panel admin solo son accesibles con un token de rol admin. Cualquier otro intento es rechazado.
Ventaja del sistema stateless: El servidor no necesita guardar sesiones en la base de datos. Cada petición lleva su propio token y el servidor solo verifica la firma. Esto funciona perfectamente con el modelo serverless.
Flujo avanzado

Recuperación de contraseña — 3 tecnologías

UUID para el token · PostgreSQL para guardarlo · Google Apps Script para el correo.

UUID v4
Token único e irrepetible
Se genera un identificador de 128 bits completamente aleatorio. Es estadísticamente imposible adivinar el token de otro usuario. Tiene una vida útil de solo 1 hora.
PostgreSQL · password_resets
Almacenamiento temporal
El token se guarda en la tabla password_resets con su fecha de expiración. Al usarse, se elimina inmediatamente. Un solo uso. No puede usarse dos veces.
Google Apps Script
Envío de correo gratuito
Un script en la nube de Google envía el correo usando Gmail. Completamente gratuito, sin servidores SMTP ni servicios de pago como SendGrid. Hasta 1500 correos diarios.

Rendimiento

Carga instantánea — localStorage

Los datos se guardan en el navegador del usuario para que el sistema se sienta instantáneo en cada visita.

  • 🐌
    Sin caché: Las funciones serverless tienen un "arranque en frío" de 1 a 3 segundos. El usuario ve la pantalla vacía mientras espera la respuesta.
  • ⚡
    Con localStorage: Los datos de la visita anterior se cargan en menos de 10 milisegundos. El usuario ve contenido de inmediato.
  • 🔄
    Actualización en segundo plano: Mientras el usuario ya ve la pantalla, la API actualiza los datos silenciosamente sin interrumpir la experiencia.
  • 📍
    Se usa en: Cronograma de la página principal, sesiones del panel admin, estadísticas del dashboard e inscripciones del estudiante.

Despliegue

De GitHub a producción en 30 segundos

  • 1
    El código se sube al repositorio en GitHub.
  • 2
    Vercel detecta el cambio automáticamente y inicia el proceso de construcción.
  • 3
    Se generan los archivos optimizados del frontend con Vite.
  • 4
    Los archivos se distribuyen en la CDN global de Vercel (más de 200 ubicaciones en el mundo).
  • 5

Visión general

¿Qué es AgendaUES?

Plataforma web completa para gestionar el evento académico más importante del año de la UMB.

🌐
Portal Público

Cronograma semanal, escenarios disponibles y cupos en tiempo real. Sin registro.

🎓
Estudiante

Inscripción a sesiones, agenda personalizada y descarga de PDF oficial con sello institucional.

⚙️
Administrador

Dashboard con estadísticas, CRUD de sesiones, gestión de usuarios y reportes en PDF imprimibles.

Problema que resuelve: Antes del sistema, la información del evento estaba dispersa. Los estudiantes no sabían horarios, escenarios ni cupos disponibles en tiempo real.

Generación de documentos

PDF oficial — sin librerías

Se usa window.print() nativo del navegador en lugar de jsPDF o html2pdf.

  • 🖨️
    window.print() usa el motor de impresión del navegador. Respeta 100% el CSS, incluyendo tablas, degradados y fuentes de íconos.
  • 📄
    @page { margin: 0; size: letter; } — elimina la fecha, URL y número de página que el navegador agrega automáticamente.
  • 📐
    print:p-[2cm] — márgenes de 2 cm aplicados vía Tailwind solo al imprimir.
  • 🔍
    Zoom en pantalla con propiedad CSS zoom (no transform:scale, que corta el scroll izquierdo).
  • 🎨
    print-color-adjust: exact preserva fondos y colores institucionales en la impresión.
/* Elimina encabezado/pie del navegador */ @page { margin: 0; size: letter; } /* Preservar colores al imprimir */ * { print-color-adjust: exact !important; } /* Tailwind print: variants */ // Ocultar toolbar en impresión: className="flex print:hidden" // Márgenes 2cm solo al imprimir: className="print:p-[2cm] print:bg-white" // Zoom siempre 100% en PDF: className="print:![zoom:1] print:!w-full"

Seguridad

JWT + bcryptjs

Autenticación sin estado (stateless) con tokens firmados digitalmente y contraseñas hasheadas.

  • 🔐
    bcryptjs: Las contraseñas NUNCA se guardan en texto plano. Se almacena un hash de 60 caracteres irreversible con 10 rondas de salt.
  • 🎫
    JWT: Al hacer login, el servidor genera un token firmado con JWT_SECRET. Contiene id, email, matrícula y rol. Expira en 7 días.
  • 🛡️
    Roles: El token incluye el campo rol. Las rutas admin verifican que sea "admin" o devuelven error 403.
  • 🔑
    Stateless: El servidor no guarda sesiones. Cada petición verifica la firma del token independientemente.
// Hash de contraseña al registrar: const hash = await bcrypt.hash(password, 10); // Verificar al hacer login: const ok = await bcrypt.compare(pass, hash); // Crear token JWT: const token = jwt.sign( { id, email, matricula, rol }, process.env.JWT_SECRET, { expiresIn: '7d' } ); // Verificar en rutas protegidas: const user = jwt.verify(token, JWT_SECRET); if (user.rol !== 'admin') return 403;

Identificador de 128 bits aleatorio. Estadísticamente imposible de adivinar. Uso único.

password_resets
Tabla temporal

El token se elimina al usarse o al expirar. La comparación usa NOW() de PostgreSQL para evitar diferencias de zona horaria.

Script en la nube de Google que envía correos vía Gmail. 100% gratuito. El backend llama a su URL con parámetros GET.

Rendimiento

Caché instantánea — localStorage

Patrón Stale-While-Revalidate: mostrar datos del caché al instante y actualizar desde la API en segundo plano.

  • ⚡
    Sin caché: El usuario espera 1-3 segundos el "cold start" de Neon. Pantalla vacía.
  • ✅
    Con caché: Los datos se cargan en <10ms desde localStorage. La API actualiza en segundo plano silenciosamente.
  • 🔄
    Donde se usa: Cronograma, sesiones del admin, estadísticas del dashboard, inscripciones del estudiante.
Resultado: La aplicación se siente instantánea en visitas repetidas, incluso si la API tarda en responder.
// 1. Cargar del caché al instante const [sesiones, setSesiones] = useState(() => { const cached = localStorage.getItem('sesiones_cache'); return cached ? JSON.parse(cached) : []; }); // 2. Actualizar desde API en segundo plano useEffect(() => { const cargar = async () => { const data = await fetch('/api/sesiones/listar'); setSesiones(data.sesiones); // actualiza vista localStorage.setItem( // guarda caché 'sesiones_cache', JSON.stringify(data.sesiones) ); }; cargar(); }, []);

Despliegue

CI/CD automático en Vercel

Cada push a GitHub despliega el sistema completo en producción en menos de 30 segundos.

  • 1
    git push → GitHub detecta el cambio y notifica a Vercel.
  • 2
    npm run build → Vite genera archivos estáticos optimizados en /dist.
  • 3
    Deploy frontend → Archivos estáticos en CDN global de Vercel (200+ ubicaciones).
  • 4
    Deploy API → Los archivos en /api se convierten en Serverless Functions de Node.js.
  • 5
    HTTPS automático → Certificado SSL gratuito, URL de producción lista.
